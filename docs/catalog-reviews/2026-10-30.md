## How to review this

1. Read the summary table, then the sections marked **Not approved** and the **Decide** notes.
2. For each approved item, check that the evidence below supports the outcome. Follow any link you want to see for
   yourself.
3. For an item you don't want to approve, comment "drop <id>" on the PR. Its `reviews` entry is then removed before
   merge.
4. Merge. The approved items become selectable in Workspace settings → Setup plan.

## Approved

### code-review (official)

**Files read, in full:** the marketplace entry, `plugin.json`, `commands/code-review.md`, README and LICENSE.

**Findings:**
- **License:** Apache-2.0, in the plugin's own LICENSE.
- **Automatic behaviour:** none. It has no hooks, MCP servers, scripts or telemetry.
- **Pre-approved commands:** read-only `gh` calls (`gh issue view/list`, `gh search`, `gh pr view/diff/list`) and
  `gh pr comment`.
- **Network:** only through `gh` to GitHub, when the command is run.
- **Cost:** a review runs 7 or more agents: Haiku and Sonnet agents, an Opus bug agent, and a validator per finding.

**Fixes made:**
- the permissions now say what it runs and costs, and that `--comment` posts without asking;
- `why` no longer claims a "history" agent that the command doesn't have;
- `requires: gh`.

**Concerns:**
- The README doesn't match the command: it describes 0–100 scores, and the inline-comment MCP tool it mentions isn't
  shipped.
- It reads CLAUDE.md, not AGENTS.md.

### commit-commands (official)

**Files read:** `commit.md`, `commit-push-pr.md`, `clean_gone.md`, `plugin.json`, README and LICENSE.

**Findings:**
- **License:** Apache-2.0.
- **Automatic behaviour:** none: no hooks, MCP servers or telemetry.
- **Pre-approved commands:**
  - `/commit`: `git add`, `git status`, `git commit`;
  - `/commit-push-pr`: also `git push` (a prefix rule, which would also match `--force`) and `gh pr create`.
- **`/clean_gone`** runs `git branch -D` and `git worktree remove --force`. It pre-approves nothing, so both still
  ask.

**Fixes made:**
- the permissions now say exactly that;
- `requires: git`;
- a note that only `/commit-push-pr` needs `gh`.

**Concerns:**
- The README says it avoids committing secrets, but the command doesn't. The gitleaks hook in `baseline` covers this.
- `/commit-push-pr` pushes without a checkpoint.

### playwright-mcp (verified-vendor)

**What was checked:**

## Not approved

### security-guidance (official): not approved, removed from `baseline`

**Read:**
- in full: the manifest, `hooks.json`, `sg-python.sh`, `ensure_agent_sdk.py`, `_base.py` and README;
- by targeted read: the other hook modules (about 11k lines of Python).

**What its hooks do:**
- **Pattern warnings** on every edit. These are local and fine.
- **An unpinned install:** a SessionStart hook runs `pip install claude-agent-sdk` with no version, into
  `~/.claude/security/agent-sdk-venv` (a few hundred MB).
- **Hidden reviews:** after each turn, and after `git commit`/`push`, it sends diffs and related files to the
  Anthropic API (newest Opus) using the token Claude Code passes to hooks. Per its README, this spend doesn't show in
  Claude Code's cost figures.
- **Telemetry:** it reports usage metrics through Claude Code's hook metrics.
- **Residue:** it leaves `~/.claude/security/` behind after uninstall.

**Why not:**
- The unpinned runtime install breaks ADR-0005 (pinned sources, no upstream installers).
- The hidden spend works against the app's cost transparency.

As `official` and in `baseline`, it would have been offered to every workspace, and could have been applied
automatically.

**Changes made:**
- out of `baseline`;
- `risk: high`;
- permissions that say all of the above;
- notes with its off switches.

**To revisit if upstream pins the SDK install.**

### cloudflare-security-audit (verified-vendor): not approved yet

**What was checked:**
- All 20 files at c1c8a8c were read; the tree hash matches the pin.
- No network calls or install steps.
- The validators use only the file system.
- Reports are written outside the project, by default in `~/security-audit-skill/<repo>/run-<N>`.

**Blocking:** the MIT license is at the repository root, and only the skill folder is copied, so the copy would lack
the notice the license requires. Fixing it needs an app change (a pinned `licensePath` for git sources); it's a
follow-up.

**Also:** on Windows the validators reject all input (`O_NOFOLLOW` doesn't exist there), so a full audit can't finish.
Guidance mode works.

**Changes made:** the permissions and `why` are corrected for when it's approved.

**Provenance is strong:**

**Findings:**
- **License:** MIT.
- **Network:** none in the 0.11.0 build. Its SECURITY.md describing an update check is out of date.

**Also:**

**Changes made:** the permissions say this, and the notes say to re-pin to 0.12.1 and review again. As a community
item it needs two reviews anyway.

  versions numerically, with a test.
- **License files:** unpacking a release kept only the binary. License and third-party notice files now stay next to
  it, also with a test.
